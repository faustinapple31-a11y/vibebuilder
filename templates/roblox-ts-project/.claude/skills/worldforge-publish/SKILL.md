# WorldForge — build & publish

## Build

```
npm install            # once
npx rbxtsc             # TypeScript → out/ (must be clean)
npm run rbxl           # rojo build → build/<slug>.rbxl
npm run serve          # rojo serve → Rojo plugin in Studio for live sync
```

`default.project.json` maps `out/server` → ServerScriptService, `out/client` → StarterPlayerScripts,
`out/shared` → ReplicatedStorage, `out/world` / `out/systems` → ServerScriptService, `out/ui` →
StarterPlayerScripts, `assets/world/WorldBake.json` → ReplicatedStorage.WorldAssets.WorldBake, plus the
Lighting / Workspace properties of the bake. The world is built at server start; **WorldForge → Bake to place**
bakes it into the place file instead (faster join, `Workspace.WorldPrebaked = true`).

## Publish (through the app only)

Publishing uses the Roblox Open Cloud API with the user's API key stored in the OS keychain by the
WorldForge app. **Never** put an API key, cookie or token in this repository, in a script, in a log or in a
prompt; never call Open Cloud from project code. The flow in the app (Roblox tab):

1. *Validate* — compiles, builds the `.rbxl`, checks the place / universe ids in `worldforge.json` → `roblox`.
2. *Publish* (`Published`) makes the version live; *Save* (`Saved`) uploads without going live.
3. Gamepasses / developer products with `robloxId: 0` are created on the universe and the ids written back
   into `design/game.spec.json` + `src/shared/catalog.ts`.
4. Audio / mesh assets from the manifests are uploaded under the user's account and their ids resolved.

If asked to publish from here: prepare everything (clean compile, `.rbxl`, catalog ids), then tell the user
to press Publish in the app — do not try to work around the credential boundary.

## Pre-release checklist

- **Security** (`roblox-opsec` skill when installed): every `Action` / remote validates its arguments,
  purchases are granted only in `ProcessReceipt` with idempotent receipt handling, no client-authoritative
  currency, damage or teleport; DataStore writes are budgeted and retried.
- **Performance**: < 45 k parts, ShadowMap, StreamingEnabled, no per-frame server loops over all players,
  particle rates reasonable (weather layer ≤ 700 particles/s), `Debris` / `Destroy` on transient parts.
- **Gameplay**: first 60 seconds show the core loop (objective on HUD, first reward within a minute);
  respawn works; no soft-locks (obby stage unreachable, tycoon button unaffordable forever).
- **Content**: original assets only (procedural or CC0 / owned), no proprietary logos / names / copied text;
  player text filtered; audience rating consistent with `targetAudience` (no realistic gore for kids).
- **Mobile**: HUD readable at 16:9 phone size, touch buttons for every hotkey, no tiny prompts.
- **Store page**: title, tagline, description and genre from `design/game.spec.json`; icon / thumbnails
  generated by the app (16:9, 1920×1080; icon 512×512).
- **Monetization**: passes are convenience / cosmetic, products consumable; prices in `priceRobux`;
  test the prompt flow in Studio (test purchases are free).

## Versioning

`worldforge.json` → `version` (semver) and `worldVersion` (bake) are bumped by the app on publish; the
world can be regenerated with the same seed to reproduce a version exactly.
